# 验证范围与报告约定

验证范围随变更确定。局部修复先做专项及必要的相邻检查；仅当修改共用机制、专项失败或发现具体连带风险时扩大范围。不要为局部界面修复重复全战役、多分辨率全量操作或反复导出 Web。

- 数据变更逐项核对源金币、生命、波次、路线、布局、禁塔与升级限制。每波完整比较出生时间线，保留预期／实际列表与首次差异；逐敌条数不称为独立场景数。
- 共用机制使用代表场景。暂停、倍速、深拷贝、重开等不在所有关卡模式重复；特殊预置塔、营地和永久卫兵仍各自覆盖。
- 使用源实际函数生成的独立样本验证转换和算法。以生成数据本身计算预期只能证明执行一致，不能单独证明与 Dove 相同。
- 动画验收分别确认源帧／像素、脚本时序／生命周期、实际渲染结果。抽样必须覆盖动作结束后的状态及隐藏／移除边界；图集引用检查和战斗数值快照不能代替。每种生命周期选代表场景，不增加全关卡逐帧回放。
- 首关、第三关、第五关短战斗检查攻击、弹丸、状态、孵化与 RNG。预期快照只在先验证源规则且说明变化原因后更新，不将自动录下的新结果当作源正确性的证明。
- 挑战以 Dove 配置和功能一致性验收。完整胜利回放默认不跑，不要求 AI 打通；不得为了通关改数值、加钱或降低难度。
- 存档检查保留两阶段结算、失败清除、最高成绩、备份恢复、未知字段、多槽隔离。界面事件链与存档单元检查各有职责。
- 日常逻辑使用 Godot headless；画面、输入、音频使用原生窗口。主分辨率检查实际行为，额外分辨率只查受到影响的布局。
- 交付时集中导出一次 Web，验证资源和隔离 PCK。浏览器由用户手动验收，报告不得将资源检查写成浏览器通过。

报告区分独立场景数、模拟帧数、数据条数和断言次数。只保留有助于定位的汇总；逐帧明细、截图、临时日志与构建包放忽略目录。历史报告不充当当前基准或当前验证结果。

默认科技验证范围与当前计数见 [默认科技](DEFAULT_UPGRADES.md) 和 `reports/upgrades_logic.json`，版本迁移见 [Dove 2.1.0.6](DOVE_2106_UPDATE.md)。配置数、模板数据条数与独立行为场景分别计数。完整比较及截图留在本地报告目录。
