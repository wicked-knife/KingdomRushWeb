# Dove 统一槽位与关卡解锁

基准为 Dove `2.1.0.2` / `e29ece82939fd73fb69bfc4b469d484a72e4dfd2`。运行时只支持统一 JSON 槽位，早期单存档迁移、按代分槽目录和槽位索引已移除；不按新增关卡或敌人增加兼容分支。

## 数据与来源

三个独立槽位位于 `user://saves/slot_1.json` 至 `slot_3.json`，每个槽位包含全部世代。`data/save/definition.json` 由冻结源的槽位模板、存储默认项及游戏设置导出，包含 1、2、3、5、6 代区间、主线终点和全部世代合计 645 星上限，记录八份行为及数据来源文件的 SHA-256。模板包含 75 个锁定塔、科技、英雄、seen、成就、背包等数据；未实现玩法只保留其字段。

内存中的关卡和模式键为整数；JSON 边界将数字对象键还原。例如 `"5":{"stars":3,"1":2},"6":{}` 表示第五关普通难度三星、第六关已解锁未通关。缺失记录表示锁定。空对象不会转换为空数组；未知字段、其他世代记录及尚未开放的模式成绩均保留。音量和 `last_slot_idx` 独立保存到 `user://settings.json`。

python tools/prepare_saves.py --check  # 不改资源，核对来源和可重现性

## 结算与解锁

`record_result(outcome)` 在胜利时保存 Dove 的 `last_victory`：关卡、模式、难度、星级及解锁塔。地图调用 `enter_map()` 才更新最佳星级、各模式最高难度、锁定塔及下一关，返回当次动画数据并清除待结算结果。重启后进入地图同样结算；重复进入不重复发放。槽位摘要会预览待结算胜利的星数，但不会提前开放关卡。

重开不结算也不清除待结算胜利；之后失败会清除它，已结算成绩保留。这是 Dove 的原版行为。第四关结算后进入第五关，第五关结算后开放第六关预览。通用算法按当前世代区间补充空记录，主线通关开放各附加区间起点，与关卡资源是否实现分开判断。英雄和钢铁挑战仍未开放。

战斗从槽位 `seen` 获取已见标记，敌人出现时记录，重开或离开战斗时保存；点击通知不再作为保存前提。塔限制合并槽位锁定表和本关限制，再排除本关 `unlock_towers`，因此第五关可用游侠和精灵营地，前四关等级限制保留。

## 保存与验证

临时文件写入后替换主文件，只用完整有效的前次槽位更新备份；主文件损坏或缺失可恢复备份。损坏且无法恢复、或格式较新的槽位不会被当作空槽覆盖。删除先将主文件、备份及临时文件移出活动路径；某一步失败则回滚，防止残留备份复活。写入失败保留本次会话数据并提示。

逻辑结果见 [dove_saves_logic.json](../reports/dove_saves_logic.json)，交付汇总见 [dove_saves_delivery.json](../reports/dove_saves_delivery.json)。专项覆盖模板隔离、JSON 往返、五个世代区间、两阶段结算、重开后失败、未知字段、第五关已见状态、塔限制、三槽隔离、备份恢复及删除失败回滚。相邻回归包含地图战斗往返、英雄大厅、主菜单、交互、二级塔及第二至五关战役。

最终结果：槽位专项 113 项、原生鼠标链路 10 项通过；地图 36066、英雄 35、槽位与开发入口 67、第二至四关 963、第五关 424、交互 448、二级塔 267 项以及菜单设置检查通过。集中导出一次 Release Web，隔离 PCK 560 个文件及槽位结算冒烟检查通过，ZIP 的 13 个条目 CRC 完整。发布包为 `build/KingdomRush-KR1-Levels01-05-Web.zip`（140772360 字节）。

原生检查使用隔离测试槽位。前四关成绩是进入第五关的夹具；第五关战斗使用已有合法回放和正常经济，经实际鼠标完成槽位选择、两次重开、返回地图及第六关预览。Web 在所有检查结束后集中导出，PCK 在隔离资源命名空间中核验模板和结算依赖；浏览器功能及持久化由用户手动验收。

本地旧格式存档已清理：删除桌面用户数据目录中的 `campaign_kr1.json.migrated`、`saves/kr1/` 及早期测试生成的 `*.slots` 目录。此前清理命令被执行策略拦截，重试已成功，无需手动删除。另清理过期发布包、可重建的导出中间文件、Python 缓存和 474 张旧验证截图；共删除 1080 个文件、347 个目录，释放约 738.73 MiB。保留统一槽位、`settings.json`、当前 Web 发布产物、最终验证证据及背景候选图。
