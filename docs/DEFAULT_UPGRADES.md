# 默认科技与本局配置

当前基准保持 Dove 2.1.0.3、提交 `1a863df00b08f6bf1018ae0b0e7e4e106b939082`。本轮开放方案 `"1"` 的弓箭、兵营、法师、炮兵、火雨、援军六分支，共 36 项；只覆盖当前已开放塔、单位和前七关 21 个组合。多候选塔升级和火枪塔已接入；其他方案、英雄参战和第八关以后另行推进。

## 数据和依赖

`tools/prepare_upgrades.py` 在隔离 LÖVE 环境求值 Dove 科技定义、目标模板分类，导出 `data/upgrades/definition.json`。价格、效果参数、中文标题／说明、图标和执行等级来自源数据；记录源提交及输入文件 SHA-256。Godot 的 `dove_upgrades.gd` 逐科技 ID 适配，不依赖标题、图标序号或字符串猜测效果。

`upgrades_contract.py` 为每项科技登记可达依赖根，并沿关卡模板依赖追踪状态、光环、援军和弹丸；校验动画、帧和声音。错误包含科技 ID、引用者和缺失内容。当前可达内容的任何缺项都会阻止资源检查和 Web 导出。未开放塔仅保留源分类，不为它们提前扩展运行模块。

## 本局配置

应用入口执行 `BattleSetup.create(CampaignLevels.load_definition(...), slot_snapshot)`。配置深拷贝通知、存档禁塔和购买科技；战斗不引用进度服务，不写回科技等级。`CampaignLevels.load_definition()` 的职责和接口保持不变；直接创建模拟器时仍为零科技。

每次初始化和重开都从基础数据深拷贝模板，再按源 `(等级, ID)` 顺序应用科技。有效等级为购买等级与所选模式 `max_upgrade_level` 的较小值，缺省使用源默认上限；这与防御塔的 `max_upgrade` 分开处理，不改存档购买等级。价格、菜单、射程和单位信息均读取本局模板。

运行时规则继续使用现有伤害、弹丸、状态和士兵模块。暴击记录弹丸伤害快照；破甲永久降低目标护甲；流血按来源伤害和护甲推算并最多叠五层；减速按源排斥狂暴；反伤延迟入队，远程伤害不会反射到发射者。法师塔联动从未联动的数值重新计算，覆盖建造完成、升级替换、出售和预置塔。

援军按本局解析的模板生成，五级可投矛，六级沿用五级单位并改变冷却和持续时间。投矛具有独立飞行、近战优先、落空贴花和落水特效；到期释放阻挡和待执行攻击。

## 地图和存档

科技房间复用地图字体、源素材和命中变换。点击高等级一次购买缺失前置等级，累计费用超过余额时保持原状态；点击已购买等级退还该等级及之后等级。界面通过进度服务的 `upgrade_summary()`、`set_upgrade_level()`、`restore_upgrades()` 和 `reset_upgrades()` 操作。

购买即时保存。撤销恢复本次打开界面时的等级；重置清零并将撤销基线设为零；完成、关闭、Esc 和右键只关闭界面。预算只读取已结算成绩，战役最好星级及英雄／钢铁挑战各一星按源计入，待结算胜利不可消费。未知字段、备份恢复和三槽隔离沿用既有存档机制。

遇到其他科技方案时保留原等级与未知字段，显示暂不支持说明，禁止科技操作及开战。当前没有方案切换入口，避免把其他方案覆盖为默认科技。

当前存档的 `upgrade_list_id` 必须存在且为字符串；数值 `1`／`1.0` 不符合当前结构，在槽位加载入口直接拒绝，不转换、不迁移。科技校验先检查字段类型，再比较方案 ID，避免地图绘制时发生跨类型比较错误。`verify_technology_slot_entry.gd` 专项检查错误类型拒绝、新槽位保存重载、地图绘制、科技界面和开战。

## 保留的源行为

- 二级火雨只开启焦土；当前源焦土基础伤害和持续时间为零，四级才增加到有效值。
- 法师塔联动第一座为 1.18 倍、第二座为 1.21 倍；移除最后一座后保留源规则的第一档倍率，后续仍从原数值计算。
- 普通兵营生命／护甲科技不影响 `re_*` 援军；高阶反伤、魔抗／减伤按源筛选影响友军和卫兵。
- 箭塔／法师造价向上取整，炮兵造价向下取整；流血推算的小数在源随机整数伤害阶段截断。没有改动源难度、星星奖励或挑战初始资源。

## 验证与扩展

`tools/upgrade_reference` 执行真实 Dove 补丁函数和行为协程，生成独立的 `tests/fixtures/dove_upgrades_source.json`。只对未开放目标提供惰性数值占位，明确列入排除清单；占位不作为当前内容的预期。40 组模板配置覆盖六分支累计等级、混合满级和科技上限，完整比较及首次差异写入本地 `reports/upgrades_source_comparison.json`。

`verify_upgrades.gd` 覆盖模板对照、21 个组合、状态／伤害／火雨／援军短场景、真实法师塔交易、连续重开／换关／换模式／换槽、三槽购买、预算不足、撤销、重置、重载、未知字段、备份恢复和挑战结算。高等级均使用独立测试槽，不访问用户存档。现有零科技战斗快照保持原基准；`upgrades_additions.json` 只列出明确新增的数据，旧图集逻辑条目与源像素继续核对，不更新历史预期来接受差异。

`upgrades_native.gd` 在 1280×720 和 1024×768 原生窗口检查 36 项说明、命中、购买音效、关闭行为和不支持方案；主分辨率还检查升级援军、流血和焦土表现。资源检查包含缺模板、子依赖、动画、帧和声音的拒绝用例。Web 导出要求科技逻辑、两种原生分辨率和资源报告均通过，且报告对应文件哈希仍有效；隔离 PCK 再检查科技元数据、图标、音频、购买和本局配置。浏览器仍由用户手动验收。

扩展其他科技时先导出源数据、登记显式 ID 和依赖，再实现模板补丁／必要行为并增加真实源样本。新英雄或关卡复用 `BattleSetup` 和既有生命周期；本轮不引入 ECS 重写或通用 Lua 执行层。
